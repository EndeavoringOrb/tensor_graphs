# KernelBench production review — 2026-10-11

Reviewed all 13 production board messages, read-only PostgreSQL job and calibration history, deployed source, and 34,321 journal lines from kernelbench.service and kernelbench-update.service. The requested seven-day journal window only returned October 11, 00:00–10:51 EDT. At inspection the service was running, the updater's latest run succeeded, the deployment checkout was clean, and no jobs were queued or running. No production changes were made.

## Prioritized fixes and improvements

1. **High: fix constant capture and correctness input reconstruction.** Messages 1, 2, and 13 report scalar-sized constants attached to larger tensors/views. The journal contains 164 occurrences of “invalid constant byte count”; the latest candidate failure was configuration 1352 at 10:03:31 EDT. Goal 8 has 20 failed baseline configurations. Job `26f17687-3cbc-4b5d-b918-f94be920fe64` records four-byte constants for two F32 [16,128] inputs with strides [1,0] and [0,1]. Audit capture semantics, backing storage spans, and broadcast reconstruction together; do not blindly repeat every scalar constant. Validate configurations during discovery, report invalid dataset entries separately from candidate failures, and regenerate a corrected immutable goal snapshot. Reported affected families include MUL, CAST, CONTIGUOUS, DIVIDE, DOT, and fused GATHER. Healthy shape/stride twins mean asking candidates to exclude configurations is not a reliable fix.

2. **High: preserve inferred view offsets in the reference correctness harness.** Confirmed in deployed `tensor_graphs_cpp/tests/fused.hpp:126–146`: outView.offset is set to zero; inferView computes dummyOutView; only its strides are copied back; flattenOutput uses the zero offset. Job `206e6d7b-2c36-4053-bf7a-eba61f53c90f`, configuration 1571, records reference -0.250919759 and candidate 0.746318579, matching messages 5–7. Carry the inferred offset and audit input-buffer selection for view kernels. Verify nonzero slices and chained views when implementing the fix.

3. **High: provide promotion eligibility for kernels that add executable coverage.** Deployed `kernel_bench/promotion.py:56` requires an existing numeric kernel speedup before full goal validation. Message 3 describes correct candidates with no executable baseline, which cannot pass this gate. Goal 8 has 102 unavailable baseline configurations out of 267 total. Add an explicit eligibility route for correctness-passing coverage additions, retaining full goal correctness, actual selection, and goal speedup requirements. Expose the reason for ineligibility through the API. Do not equate missing baseline with proven performance benefit.

4. **High: expose executed goal workloads and planner selection reasons.** Of 17 candidate promotions, 10 ended unselected with selected_count=0, including six CONTIGUOUS variants. Messages 8–11 show agents pursuing large microbenchmark wins that do not translate to executed goal work. Publish per-configuration execution counts, bucket weights, engine/memory placement, selected kernels, measured contribution where available, and elimination/selection reasons. Distinguish discovered rewrite alternatives from executed workloads. Perform a candidate planning/selection check before expensive baseline and candidate inference; skip full benchmarking when selection is zero. Existing verifyDiscoveryGoal checks root, buckets, and weights; extend provenance checks if stronger graph equivalence is needed rather than treating agents' snapshot-mismatch hypotheses as established.

5. **Medium: make native interface failures stop calibration promptly.** Journal evidence: 330 missing `kernel_bench_test_diagnostics` errors between 01:29 and 01:43. Later jobs execute successfully, and the deployed code now checks recorded native interface versions, so this is an earlier incident with some mitigation already present. Add an actual module export/version preflight after building, key cached build markers by source/interface identity, and stop a calibration batch on infrastructure incompatibility instead of failing hundreds of configurations independently.

6. **Medium: make deployment refusals actionable.** The updater refused a dirty checkout 41 times from 00:05 through 01:24. The checkout was clean and updates succeeded at review time. Preserve the refusal, but log the changed paths, alert once per distinct failure, and show the stalled deployment state to operators. Keep mutable caches, generated output, and benchmark records outside tracked deployment files where practical. The logs do not establish which files caused this incident.

7. **Medium: improve promotion statistics near the 1% gate.** Dot_Skinny_F32_CUDA passed at 1.01568x, close to the default 1.01 goal gate; unselected candidates range approximately 0.991–1.001x despite executing no candidate instructions. Use repeated paired measurements with alternating baseline/candidate order, report dispersion and uncertainty, and remeasure borderline results. Avoid treating instruction counts as cost estimates. Message 13's conclusion that all reference arithmetic is a dead end is broader than the evidence: the measured ADD and POWER replacements lost, but that does not prove DIVIDE, transfers, or other implementations cannot improve.

8. **Medium: diagnose COPY_TO coverage by actual topology.** Messages 5–7 report all 59 COPY_TO configurations lacking executable coverage because copy_cuda_cuda requires distinct CUDA spaces on a single-GPU machine. Audit this against actual mappings, distinguish same-device, cross-device, host/device, and storage transfers, and expose topology rejection reasons. Provide separate appropriate kernels. The topology root cause is agent-reported; this review confirmed unavailable baselines but did not reproduce the mapping failure.

9. **Medium: validate registration errors before native static initialization.** Job `ba52386c-395d-4611-85c3-d3528fba3a7e` aborts with signal 6 at load: `dtypes.size() != min_num_inputs`. Add registration arity checks to lint/compile diagnostics where feasible and return an actionable contract error with source location. Native crash containment and artifacts already work; improve the feedback and avoid spending a full build on errors detectable earlier.

10. **Lower: improve calibration and service diagnostics.** Goal 8 calibration is 145 measured, 20 failed, and 102 unavailable; failed baselines currently collapse to “Baseline correctness failed.” Preserve the underlying exception, configuration/input details, and classification. Journal subprocess failures are logged as INFO and often lack a job/configuration context; include those identifiers and severity in summary events. Cost estimation emits six missing-record warnings, and an earlier 02:58 goal build failed to find an execution graph: report missing records and planning failures explicitly. Bucket correctness logs also show cosine values above 1 (including 1.0002487); audit accumulation precision and the displayed metric rather than drawing correctness conclusions from it alone.

## Performance work worth investigating after harness repairs

This supports prioritizing measured, executed SUM/DOT work. Agents suggest small-N GEMM opportunities, but the bandwidth/headroom claims were not independently benchmarked in this review. Repair malformed DOT configuration 1549 before using it to assess general candidates.
