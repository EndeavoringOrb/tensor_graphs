# Selection-relaxation bound and root primal heuristic

Code: `tensor_graphs_cpp/core/plan/relaxation_bound.hpp`, `core/plan/propagators/relaxation_bound.hpp`, `core/plan/primal_heuristic.hpp`. Tests: `test.exe --relaxation-bound` (randomized brute force), oracle cases 29–32.

## The relaxation

For one bucket, drop memory, dispatch order and the cache budget, and keep only the selection: the root is active, an active class picks one of its remaining alternatives (the root domains after root propagation), and the chosen alternative's children are active. CACHE/INPUT alternatives are free and always allowed. Each alternative has its simulated duration (`MakespanSimulator`: INPUT/CACHE and views take 0, an infinite cost simulates as 1, an empty engine list runs on CPU engine 0) and occupies its engines.

Every engine executes its operations one after another, so for any plan the bucket makespan is at least `max_e load_e`, where `load_e` is the total duration of selected operations on engine `e`. For any probability vector `λ` over engines, `max_e load_e ≥ Σ_e λ_e load_e = Σ_selected w_λ(a)` with `w_λ(a) = duration(a) · Σ_{e ∈ engines(a)} λ_e`. So any lower bound `B_λ` on the minimum weighted cost of a selection is a lower bound on the bucket makespan, and on the objective after weighting buckets.

## The recursion

Groups: classes linked by COPY_TO alternatives hold the same logical tensor (a CPU and a GPU copy); `group(c)` is a union-find class. `GND(c)` (necessary groups) is the intersection over `c`'s alternatives of the union of each child's group and `GND(child)`; if `c` is active, then for every `G ∈ GND(c)` some member of `G` is active in `c`'s selected sub-DAG (induction on the DAG). Since a COPY_TO only copies within its group, an active group has an active member whose selected alternative is not a COPY_TO; its weight is at least `mp(G)`, the minimum weight of the group's non-COPY_TO alternatives.

For each class `c`, the recursion computes `L(c)` and a support set `S(c)` with the invariant

> for every plan in which `c` is active, `L(c) ≤` the weighted cost of the plan's active classes that lie in `S(c) ∩ T(c)`, where `T(c)` is `c`'s selected sub-DAG.

`L(c) = min over alternatives a of [ w(a) + Σ_{k ∈ A} L(k) + Σ_{G ∈ E} mp(G) ]`, where `A` is a set of positive children with pairwise disjoint supports, and `E` is the set of necessary groups of `a`'s children, other than `group(c)`, whose members avoid every support in `A`. Proof of the invariant: the plan selects some alternative `a`. Its own weight is paid by `c`, which is in `S(c)` and in no child's sub-DAG. Each anchor `k` is active, and by induction contributes at least `L(k)` from `S(k) ∩ T(k) ⊆ S(c) ∩ T(c)`; these sets are disjoint. Each group in `E` has an active producing member in `T(c)`, which is a distinct class for each group (groups are disjoint), lies in `S(c)`, and lies outside the anchors' supports and outside `c`'s own group. `S(c)` is `{c}` plus the union, over all alternatives, of every positive child's support and every charged group's members (a superset is always safe). A class whose `L` is zero gets an empty support. Several anchor orders are tried and the best sum is used.

**Cycles and groups.** The bucket graph's cyclic components (copies back and forth, views and their inverses, and from `--seq-len 2` on a decode step's one-position tensor and the slice of the two-position one it can be cut from, with the scatter back) are unrolled: a component of `k` classes becomes `k` levels of copies, the lowest with only alternatives from outside the component, each higher one also with the component's internal alternatives reading the level below (a cycle-free selection inside the component is a path of at most `k` classes). Components above 16 classes are not unrolled (the bucket is then skipped as cyclic). A group is a set of classes that hold the same information: classes linked by copies, and the classes of a cyclic component (each can be derived from the others; a cycle-free plan still produces some member through an alternative from outside the component). A group's members are its classes reachable from the root, level copies included (when a cycle is entered through another member, only lower levels of a class can be active); unreachable classes are never active. Oracle case `41_cyclic_component_group`; `test --relaxation-bound` also checks 2000 random graphs with such cycles (layers of a full tensor, its part and a GPU copy) against brute force over cycle-free selections.

**Regions.** Shared history (for example the residual stream) appears below every child, so supports overlap and only one child could be an anchor. To avoid that, take the root's necessary groups ordered by the size of their descendant sets and keep a longest containment chain `G_1, G_2, …, G_k` (dynamic program over the groups; a greedy pass stops at the first group nothing larger contains), where `Desc(G_i)` is the union of the members' descendant sets. Region `R_i = Desc(G_i) \ Desc(G_{i-1})`, and the final region is `Desc(root) \ Desc(G_k)`. In each region the recursion runs with every class below the region given `L = 0` and an empty support. A group may be charged only if all its members lie in the region. Then all supports used in region `i` lie in `R_i`, and the regions are disjoint. Every plan has an active member `m_i` of each `G_i`, so the plan's weighted cost is at least `Σ_i min_{m ∈ G_i} L_i(m) + L_final(root)` (a link whose group has a member below the region contributes 0).

`B_λ` is that sum. The propagator maximizes over `λ` (golden-section search on two engines, a fixed set of weightings otherwise); every evaluated `λ` is valid by itself.

**Fractional supports (claims).** The load recursion generalizes supports to claims: `φ_c(x) ∈ [0, 1]` is the fraction of class `x`'s own weight that `c` relies on, with the invariant `L(c) ≤ Σ_x φ_c(x) · w_plan(x)` for every plan with `c` active (`w_plan(x)` is the duration of `x`'s selected alternative, 0 when `x` is inactive). A set support is the special case `φ ∈ {0, 1}`. For an alternative `a`, the children are packed greedily (every child tried first): an anchor `k` is taken at the largest `α ≤ 1` that keeps the cover (the sum of the claims taken so far) at most 1 on every class, adding `α·L(k)`. The fraction `g` of a child's own weight that is still free adds `g` times its cheapest weight. A charged group adds `γ·mp(G)`, where `γ` is the fraction free on all its members (whichever member produces it carries the claim). For a plan selecting `a`, every class is claimed at most once in total, so `w(a)` plus the packing is at most `Σ_x φ(x) w_plan(x)`. `φ_c` is 1 on `c` plus the componentwise maximum over alternatives of their packings, each scaled to what it must justify (`L(c) − w(a)`; nothing when `w(a) ≥ L(c)`). The plan picks one alternative, whose scaled claims lie below the maximum. Claims stay inside the set support of the region (every positive child's support and every charged group's members), so the interval bound's path recursion may keep using `L` with set supports.

Fractions matter when a class is shared by children that each need only a little of it. On Gemma the logits are a concat tree of chunk dots. Each chunk can take a cheap route through a transposed slab shared by several chunks, needing 1.45 of the slab's 17.5, or a GPU route through the GPU copy of the transposed embedding, needing 7.9 of its 149. With set supports every chunk's support held these shared classes and only one chunk counted. With claims, all chunks count until the shared class is used up. The plain load bound on Gemma `prefill+decode --seq-len 0` (Linux box) rises from 114.97 to 232.83. Oracle case 38 (a child also claimed through its sibling) fails if a used-up child is credited again.

**Degenerate decompositions.** When a region holds more than 32768 classes (no useful chain of necessary groups), the load recursion would take minutes: the bucket gets no relaxation bound (0), and for the primal heuristic `evaluate` only fills cheap estimates (each class's least weighted cost over its alternatives plus its children's estimates, shared classes counted per use).

**Floating point.** The simulator accumulates engine finish times in float. Over `n` operations it can undershoot the exact sum by a relative `n·2^-24`, so the stored bound is `B·(1 − (n + 64)·1.2e-7) − 1e-7`, rounded toward zero. `n` counts the original classes with an alternative of positive duration: only those add rounding (views add exactly 0), each finish time comes from its predecessors' by a maximum (exact) and one addition, and a plan selects each class once, so the chain of additions behind the makespan is at most that long.

## Case splits (threshold split)

Some sharing is genuine. The Gemma logits are a concat tree of chunk dots, and each chunk can also come from the GPU, where every chunk reads the same GPU copy of the transposed embedding. The supports of the chunks then overlap in that copy and the recursion credits only one chunk. A case split on the shared class repairs this.

The recursion runs on a branch `(F, Z)`: plans that select no class of `F` (alternatives with a forbidden or infeasible child are skipped, classes without a usable alternative are infeasible) and only classes outside `Z` are counted (they take `L = 0` and are removed from every support). Its invariant is the same with claims outside `Z`: `L_{F,Z}(c) ≤ Σ_{x ∉ Z} φ_c(x) w_plan(x)` for every plan of the branch with `c` active, and the region value `V(F, Z) ≤` the plan's cost on the region minus `Z` (`+∞` when no target is feasible, i.e. the branch has no plan). `S(x)` below is the set of classes `x` claims.

*Threshold split* for a target `θ`, starting from `F_0 = ∅`, `Z = ∅`. In round `j`, evaluate `V(F_j)`. If it is at least `θ`, the region is worth `θ`. Otherwise every class `x ∉ F_j` with `L_{F_j}(x) ≥ θ` joins `F_{j+1}`, and so does a class `x` (tried in order of the value its sharing cost overlapping children) with `L_{F_j}(x) + V(F', S(x)) ≥ θ`, where `F'` is the forbid set at that point. When no class joins, the region is worth `min(θ, V(F_final))`. Why: a plan either avoids every class of the final `F`, so it is a plan of that branch, or it avoids the classes added before some `x` and selects `x`. Then it counts `L(x)` on `S(x)` (computed under `F_j`, a subset of what it avoids) and, disjointly, `V(F', S(x))` on the rest of the region, which together reach `θ`. The bound bisects `θ` (doubling from the plain value, then 40 steps at most) and keeps the best value found; every tested `θ` is valid on its own. `probeRegion` is the same split nested on single classes (`min(V(F ∪ {x}, Z), L(x) + V(F, Z ∪ S(x)))`); it is kept for tests and diagnostics but not used by the propagator.

*Nesting.* In the with-test the rest `V(F', S(x))` may be any valid bound of that branch, in particular a threshold split of the branch for `θ − L(x)`, nested `depth` levels deep. Each level costs about 3 to 5 times the previous one.

*Refinement.* The search below the root does not raise these bounds, so `SearchEngine::refineRootBound` spends up to half the remaining time after the root heuristic on deeper splits, one level at a time (`RelaxationBoundPropagator::refine`; a level's proven region values seed the next level's bisection, and the deadline only stops proving). After each level the root node's bound becomes the weighted sum over buckets of `max(root bucket bound, refined relaxation bound)`. The root bucket bounds are snapshotted after root propagation, because the state's bucket bounds stay stale after the heuristic restores the root until the next propagation. Restored and left-child nodes keep at least their parent's bound (their box is a subset), so the certified bound never decreases.

The propagator applies the threshold split (4 sharing candidates per round) to every region at the best `λ` of the golden-section search. On Gemma `prefill+decode --seq-len 0` (Linux box) it lifts the load bound from 114.97 to 161.28 (the logits region goes from 8.07 to 54.38) in about 0.1 s, and refinement reaches 183.5, 193.5 and 201.3 at depths 1, 2 and 3 (0.7 s, 4.1 s and 22.7 s). Tests: `test --relaxation-bound` checks `evaluateProbed` (probes and threshold splits on every region) against brute force on the random, layered and logits-style chunked graphs; oracle case 37 (two chunks sharing an expensive route) fails if the plans that use the shared class are not charged.

## Global split

The region decomposition can hide a class. When a region's target group can be produced cheaply by one member (on Gemma, the GPU cast of the embedding, nearly free at `λ_gpu ≈ 0.01`), the region is worth little. Later regions then treat every class of that region as already paid, including the expensive member they actually need (the 40 ms CPU cast that every CPU logits chunk reads). `evaluateGlobalSplit` splits on such a class `x` across all regions:

- *x selected* (any copy of it: cycle unrolling makes level copies with the same alternatives): the copy's region costs at least `L(copy)` (the copy is active and its claims lie in the region), so that region is worth `max(value, L(copy))` and the others are unchanged. The branch gains the smallest raise over the copies.
- *x avoided*: every copy is forbidden in every region. Regions are evaluated in chain order, and a class with no usable alternative left is infeasible for later regions too: each alternative records its children below the region (`AltInfo::below`).

The bound is `min(avoided, used)`, maximized over the 8 classes (by original class) with the largest raise. Region values already proven by threshold splits at the same `λ` hold for every plan, so they floor both branches. Classes are counted only through their own region in each branch, so nothing is counted twice. For this to bite, the masked recursion decides positivity dynamically: a class whose only free alternative became infeasible (a view of the forbidden class) gets the cost of its remaining alternatives instead of a structural 0.

On Gemma `prefill+decode --seq-len 0` (Linux box) the split on the CPU embedding cast gives `min(avoided 264.09, used 272.60)`, raising the bound from 232.83 to 264.09: the final gap drops to 4.81%. Tests: `test --relaxation-bound` (70552 global split checks against brute force), oracle case 39 (a split that adds `L(x)` to the region instead of raising it to `L(x)` claims 8 > optimum 5).

## Interval bound

The load bound treats the engines as if all work could overlap. Decode graphs are mostly sequential, so a second bound splits time into windows.

**Chain and windows.** Take the root's necessary groups ordered by descendant-set size and keep a chain `G_1, …, G_k` in which every member of `G_i` necessarily depends on `G_{i-1}` (`G_{i-1} ∈ GND(m)`). Let `t_i` be the earliest finish of an active member of `G_i` (`t_0 = 0`; the last window ends at the root's finish). The earliest member of `G_i` depends on an active member of `G_{i-1}`, so `t_{i-1} ≤ t_i`. A class `x` with `G_{i-1} ∈ GND(x)` starts after some active member of `G_{i-1}` finishes, so at or after `t_{i-1}`. A class in the selected sub-DAG of the earliest member of `G_i` finishes by `t_i`. So the classes counted for window `i` (necessarily after `G_{i-1}`; the recursion only collects them below a member of `G_i`) run inside `[t_{i-1}, t_i]`. Necessary groups are transitive, so any subsequence of the chain is again such a chain. The bound uses every `s`-th link for strides `s = k/4, k/16, …` (down to 16 windows) and keeps the best.

**Window value.** On every engine the window's load is at most its length. Any dependency chain of window classes runs sequentially inside the window. So for `μ ∈ [0, 1]` and any probability vector `λ`:

> `t_i − t_{i-1} ≥ μ · (duration of a chain) + (1 − μ) · Σ_e λ_e load_e(window)`.

`P(c)` extends the recursion of `L(c)`: the load part uses the same anchors, supports and charged groups (scaled by `1 − μ`). The chain part continues either through one anchor (whose `P` replaces its `(1 − μ) L`, so its load is still counted once) or through any child (`μ` times its window critical path, no load). A class's own duration enters the chain part only if it is counted in the window. The window value is `max(critical path, max over λ, μ of min over the members of G_i of P)` (golden-section search on `λ`, `μ ∈ {0, 0.2, …, 0.9}`). `μ = 0` is the load bound, `μ = 1` the critical path. The window values add up to a lower bound on the bucket makespan. The propagator stores `max(load bound, interval bound)` with the same float margin.

On Gemma decode the interval bound is 31.25 per decode bucket (load bound 29.99). Tests: `test.exe --relaxation-bound` checks strides 1, 2 and 3 against the minimum makespan over all selections and dispatch orders of 6000 random graphs. Oracle cases 33 (parallel work that does not depend on the opening link must not be charged to the window) and 34 (a sequential chain with engine choices: load bound 2.5, interval bound 5 = optimum) pin the inequality.

**Exact window value.** When a window's selections (below a member of the closing link) can be enumerated within 20000 search nodes, the window value is the exact minimum over them of max(chain, engine loads, one-machine values), shared classes counted once. Every plan's window is at least its chain and each engine's load. It is also at least, for each engine, the shortest head of the selection's operations on it (chain below the operation inside the window) plus their load plus their shortest tail (chain from the operation up to the target): the engine runs them one at a time, the first cannot start before its head and the last is followed by its tail. On Gemma `--seq-len 1` this raises the decode flexible bound from 12.89 to 13.05 (the LM head window: the GPU's slices are followed by copies and concats). Oracle case `40_one_machine_window_tail` (a longest-tail variant claims 9 against the optimum 7).

The enumeration (depth first over the classes the partial selection needs) prunes a partial selection once any of these reaches the best value found:

- its largest engine load;
- its chain bound: chosen classes take their alternative, the others their best alternative over the same bounds of their children;
- on an engine, the load so far plus, over the distinct needed and unchosen classes, the least each adds there (over its alternatives that keep their engines below the best value; an alternative elsewhere adds 0);
- on an engine, the load so far plus the load along the heaviest route below one needed class (maximum over children, so shared classes are not counted twice).

Classes that add nothing for any selection (every alternative unweighted, every child such a class) are left out, and alternatives that are then identical (own duration, engines, remaining children) are tried once. None of this changes the value. `test --relaxation-bound` checks that with and without it (`setExactWindowPruning(false)`) the flexible-window values agree on the random graphs.

**Cut DP (threshold).** For larger windows (up to 512 classes), a bisection on `T` proves that no selection has max(chain, loads) ≤ `T`:
1. Alternatives whose shortest chain below (head) plus shortest chain up to a target (tail) exceeds `T` are removed, to a fixpoint. They cannot appear in such a selection.
2. A dynamic program over the window's classes, parents first, enumerates the remaining selections exactly. A state is the set of required, not yet processed classes, so each class is processed once and shared classes count once. Each state keeps a Pareto set of points: engine loads plus, for each required class, the longest chain from the target down to it. A class may take an alternative only if that chain plus the alternative's duration and its children's shortest heads is at most `T`.
3. If the minimum largest load over the surviving selections exceeds `T`, the window is longer than `T`.

The DP also carries the one-machine value of the exact window value: a point holds, per engine, the shortest head (shortest chain below the chosen alternative) and the shortest tail (the tail into the class, final because parents are processed first) of the operations placed on it so far, infinite before the first; the selection's value is the largest over engines of head + load + tail (the load alone on an engine without operations). On Gemma `--seq-len 1` it adds 0.12 (the LM head window, whose enumeration does not finish), flexible windows 13.05 -> 13.17, with long windows 13.25 -> 13.37. A longest-tail mutant fails `test --relaxation-bound` (cut-DP checks run with the exact enumeration disabled).

Limits keep it valid. Past 5000 states the DP gives up (no proof). Past 16 Pareto points the two closest are merged into their componentwise minimum, which only weakens pruning and lowers the computed minimum. On Gemma this exact DP needs at most a few hundred states per layer-sized window, because the dataflow cut is narrow.

**Window partitions.** Runs at strides 1, 2, 4, … (each also shifted by half a stride) give windows between different links. Any sequence of consecutive windows covering the chain, followed by the final window to the root, is a valid chain of disjoint time windows. An interval DP (`bestWindowPartition`) keeps the best such partition. The strides stop at the first stride whose own total does not improve the best (each doubling costs about twice as much).

**Flexible windows.** Uniform strides rarely align with a model's blocks. A parallel branch (an MLP's up projection, which depends on the normalized input but not on the gate projection) belongs to no stride-1 window: it is not necessarily after the gate link, and the next link's work does not depend on it. `flexibleIntervalBound` values every window between chain links `a < b` with `b − a ≤ 8` (windows above 512 classes count 0), each like a stride window (exact value when the enumeration finishes, otherwise the λ / μ values and the cut DP), and a DP keeps the best partition of the chain into consecutive windows ending at the root. Any such partition is valid, as above. Windows whose exact enumeration finishes are valued in parallel; the others (λ / μ values, cut DP) too, each thread with its own weight table. It is the first refinement level after the root heuristic (the stride windows follow later). On Gemma `prefill+decode --seq-len 1` (Linux box) it gives 12.89 against 12.77 for the stride windows, in about 1.4 s. The primal heuristic splices each partition window's best selection into its plan (window moves, `improveByWindows`; see below).

**Long windows.** A parallel branch can fork more than 8 links before the window where it joins (on Gemma decode: the K projection, norm and RoPE fork at the layer's normalized input and join at the attention scores), and no window of the flexible partition holds all of it. After the window moves (next refinement level), windows of 9 to 24 links ending at a boundary of the flexible partition are valued by the cut DP alone (their exact enumeration rarely finishes), and the partition DP runs again over all windows. On Gemma `--seq-len 1` this raises the decode bound from 13.05 to 13.25, in about 8 s (all windows up to 24 links would take 200 s; merging only consecutive partition windows gains 0.006). `test --relaxation-bound` checks (1, 4) and (2, 8) short / long lengths against the minimum makespan. Tests: `test --relaxation-bound` checks lengths 1, 3 and 8 against the minimum makespan.

**Identical buckets.** The propagator serializes each weighted bucket's relaxation (`relaxationSignature`) and computes each distinct relaxation once; decode buckets usually share one. Windows are evaluated in parallel.

On Gemma decode the interval bound is 36.06 per decode bucket (load bound 29.99), in about 1.9 s at the root. Tests: `test.exe --relaxation-bound` checks the exact and cut-DP window values (with enumeration disabled), and the window partition over strides 1–4 with every phase, against the minimum makespan over all selections and dispatch orders of 6000 random graphs.

## Where the bound lives

`RelaxationBoundPropagator` runs once, as a GLOBAL batch at the quiescence of the first (root) propagation, and stores `SearchState::bucket_relaxation_lower_bounds`. `updateLowerBoundBucket` takes the maximum with the other bucket bounds. Nodes below the root only have smaller domains, and the relaxation over a superset of plans is still a lower bound, so the stored values stay valid in the whole tree and the certified bound (`docs/core/search_gap.md`) never drops below their weighted sum. Zero-weight buckets are skipped. Cyclic buckets get no bound. A bucket whose root has no feasible alternative in the relaxation has no plan at all, so the propagator reports a conflict.

On Gemma decode the bound is 29.99 per decode bucket (CP-SAT proves the exact relaxation optimum, min-max engine load, at 30.36; the old root bound was 0.53). It takes about 60 ms for all buckets.

## Primal heuristic

After root propagation, `SearchEngine` builds complete plans and evaluates them like any leaf:

1. Per bucket and per engine weighting `λ`, the recursion above is evaluated and each class's region value is used as its marginal cost estimate. Classes are visited parents first. An active class in a weighted bucket picks the alternative minimizing its weight plus the estimates of children that are not yet active.
2. Caches: a CACHE/SCATTER-dependent alternative may only be used for a base whose cache variable still allows 1. The cache set is the set of bases whose dependent alternatives the weighted buckets chose. A cached base must be selected in every bucket and fit the space's cache budget; offending bases are disallowed and the selection is repeated.
3. Zero-weight buckets (for example the "full" bucket) do not count in the objective, but every class whose base is cached must be selected there too. Their selection is a covering extraction: parents first, each active class picks the alternative whose children can still reach the most inactive target classes (ties by estimate).
4. Dispatch order: list scheduling with the simulator's semantics (earliest possible start, ties by the longest remaining path).
5. The cheapest plan by simulated weighted makespan is applied below the root: cache and selection variables are fixed, and start ranks follow the dispatch order inside their windows (pinned starts are kept). Then every propagator runs. The plan becomes an incumbent only if propagation succeeds and every variable is fixed; its cost is computed by the normal leaf evaluation. The state is then restored to the root.
6. Local search: from every distinct initial plan (one per weighting), each weighted bucket is improved in parallel by single-class switches. Newly needed children are completed greedily, unneeded classes are released, cached bases stay selected, and cache-only alternatives stay limited to cached bases. Moves that raise the maximum engine load are skipped; others are kept only if the list-scheduled makespan decreases. A start stops when a full pass finds no improvement (or at the program deadline). Each improved plan is validated as in step 5.

The heuristic never changes a domain or bound that survives the restore, so it does not affect bound semantics.

7. Window moves (`improveByWindows`, after the first plan is validated and the flexible windows are computed, and again after the long windows): for each window of the bound's flexible partition whose plan time (from the first finish of a member of the link before it to that of its closing link) exceeds the window's bound, a search of the window's selections gives selections with a small window value: the exact enumeration with 200000 nodes (2000000 when the plan is more than 0.06 over), half of them trying shortest chains first and half least total work first, keeping its best selection when it does not finish; that selection also polished by a local search on the window value (single-class switches, newly needed classes take their least-work alternative; classes that add nothing inside the window stay unchosen). Windows the plan already meets are skipped. It replaces the plan's choices in every weighted bucket with that relaxation at once (`spliceWindowSelection`). Classes it needs and does not select are activated greedily and may read any base that can be cached from the cache, which adds the base to the cache set; classes nothing needs any more are dropped, and cached bases no bucket reads from the cache any more leave the cache set. Newly cached bases are then activated in every bucket, memory caps and cache consistency are checked, and the move is kept if the weighted makespan drops. This changes many classes together, which single-class switches cannot: a layer's norm and its copies, or how the LM head is split over the vocabulary (on Gemma `--seq-len 1`, part of it on the CPU in parallel with the GPU, with the weight slices cached instead of the halves). Then local search runs again and the plan is validated if it predicts at least 0.1% better.
8. Cache-set moves: local search records cached bases whose required selection blocks an otherwise load-reducing move. For those bases (all of them together, then each alone) the base is dropped from the cache set and local search runs again with the base releasable. The result is kept if no weighted bucket still uses the base's cache-only alternatives and the weighted makespan drops. The improved plan is validated as in step 5.

## Proof phase: largest box first

Once the root heuristic has an incumbent, the remaining search mostly makes proof progress. The queue then pops the open node with the largest box first: its stored log2 volume when volumes are measured, otherwise the shallowest node. Popping a node refreshes its box by propagation (closing it on a conflict) and splits it, so the regions that dominate the frontier shrink first. This only reorders the queue; no node is dropped.

On Gemma decode the accepted implementation (H-G4b) reaches its first incumbent (39.33) about 26 s into the program and its local optimum (37.02) immediately after. The final gap is 0.190 against the 29.99 bound, and the normalized primal-dual integral is 0.225 (baseline 0.992).
