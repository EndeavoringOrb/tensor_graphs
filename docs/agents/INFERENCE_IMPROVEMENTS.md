## Resume: independent buckets (2026-10-15)

Family planning, hull normalization, relocation, and representative weighting have been removed. Every requested bucket goes through ordinary joint planning with its actual domains and explicit workload weight. There is no neighbor seeding. The earlier architecture and results below are historical.

SCATTER remains update-only with a stable owner tag and no base/CACHE operand. Partial-update alternatives require a real persistent cache candidate; initialization runs a compiled full graph before cached partial execution. Mask recognition uses exact equality to the finite TGConstants::NEG_INF sentinel (-1e9), an explicitly accepted numerical approximation. See [the implementation plan](../reviews/families.md) and [the baseline record](../reviews/families_baseline.md).

Builds require linting; --no-lint was removed. Build outside the sandbox using `.venv/Scripts/python.exe build.py --t bindings test`.

### User decisions
- Keep the given full-sequence graph; never hand-insert KV caches or slices; saturation must find partial reuse.
- Never prune saturation alternatives for speed (only unsound ones); make saturation/search fast and parallel.
- Bucket design: **shift families** (one plan per interval of positions; every member resolved to a concrete
  CompiledGraph at compile time, so the executor stays a simple loop). A decode bucket is [1]->[1], a prefill bucket [N]->[1].
- Cross-bucket validity: **buckets keep caches valid** (each bucket recomputes its dirty region of every cached value).

### Current architecture (what is implemented)
- Region analysis (core/plan/bucket_regions.hpp):
  - dirty excludes elements that depend on input padding (Settings::padded_inputs, input -> axis; the LLM session pads
    token ids past the request, axis 1) and elements outside "live" (what the full output can need, e.g. masked scores).
  - needed += dirty ∩ live ∩ finite ∩ support for every non-root value ("keep valid").
  - live map cached once per graph (RegionFacts::liveCache); fast subtract and list intersection (misc.hpp).
    Region time per bucket at seq 1024: 0.2-0.7 s.
  - FamilyRegionNormalizer: per box dimension a bound moves linearly with the shift or is widened to the family hull;
    bounding-box fallback when box counts differ (mask staircases).
- Shift families (Planner::planFamilies, core/plan/bucket_families.hpp, Settings::bucket_families):
  - Normalizes families in parallel, plans one representative per family (weight = members' mean weight) together
    with the other buckets; rules get facts without support/finite for family plans (reductions over the whole extent).
  - After the search, a witness and a verifier (each up to 4 candidate members, skipping shifts whose bounds equal
    integers the graph uses) are saturated and prepared like the representative and must line up with its egraph.
    The rep->witness difference (view offsets, integer constants linear in the shift) is the relocation; it must
    reproduce the verifier. Every member's CompiledGraph is the relocated representative.
  - bindings.cpp: block sizes whose smallest is 1 make each block need only its last logits row; each size is a family.
- Other planner/rewrite work: SlicePushDownFused (row-local fused kernels on row slices); scatter forms tagged with
  their owner class (contentHash "scatter-into:..."); ScatterPullUp treats a partially dirty INPUT as updated and uses
  cached live regions; faster ConsumerWeightReuseRule and SlicePushDownElementwise.match; two-start root heuristic
  (covering gated at 3x / always), local search before validation, cache-set moves capped at 30 s.
- NEW, NOT YET TESTED: addCacheBases() "add cache base" move (primal_heuristic.hpp, called before improveCacheSet in
  search_engine.hpp; log line "cache-set moves ... added=N dropped=M").
- Runtime: `Settings::resident_weights` (LLMSession(resident_weights=True)) preallocates weights once (511 MB);
  LLMSession opts out of Windows power throttling; thread-pool workers spin up to 50 us before sleeping.
- Kernels: GemmaRMSNormFill_{Rows,Heads}_F32_3D(_Threaded), Sum/Max_F32_LastAxis_NEON(_Threaded),
  BF16_Transposed_GEMM_NEON_WStream_Threaded / _v2 / _v3, Scatter_F32_Rows(_Threaded) (all calibrated; see below).
- tests/inference_session.py: SEARCH_MARGIN_SECONDS=75, Python-built token buckets from inference_cases.py,
  resident_weights=True,
  TG_DISABLE_OPENCL, TG_SKIP_RELAXATION_BOUND, log_cost_calls=False, repo_path=<run dir>/repo.

### Key findings for the family scheme (seq 1024)
- Decode family alone ({1}): decode member predicted 12.3 ms. {1,8} (logs/diag/bf18): decode 13.5 ms, 8-token
  block 22.1 ms (pp8 needs <= ~11 ms: LM head 3.4, projection GEMMs 5.3, attention dots over the 1024-key hull 4.6
  (Dot_F32_3D_CPU_Neon), copies ~2.4, norms/gelu/elementwise ~3).
- {1,8,64,512} (logs/diag/bf1024): plans poor (decode ~93 ms, 8-block 86, 64-block 111, 512-blocks 254/390).
  Cause (verified with TG_DEBUG_CLASS): when a scatter form is valid, slice-pushdown rules give ONLY the scatter form
  ("never both", avoids a cycle), so restricted computations of src are reachable only if src is cached. The root
  heuristic's cache set leaves e.g. the softmax "-max" node uncached, so decode recomputes it at full size.
  addCacheBases targets this.
- Compile time: normalization ~52-60 s, saturation ~21-27 s (512-blocks alone saturate in ~100 s each), search to
  the deadline, probes ~40-100 s. Total ~550 s with deadline 525: tight.
